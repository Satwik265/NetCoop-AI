# Organizer Telemetry Schema Specification

This document details the telemetry format generated by the IIT Bhubaneswar hackathon organizer's Jupyter/Colab notebook (`data/organizer/Mock_data_builder_netScoopAI.ipynb`) and reproducible CLI generator (`data/organizer/organizer_generator.py`).

---

## 1. Top-Level Structure

Each snapshot is a JSON object with a top-level `timestamp`, `device_id`, nested `metrics` object, and a device health `status` string:

```json
{
  "timestamp": "2026-10-31T12:00:00+00:00",
  "device_id": "SW_CAMPUS_1",
  "metrics": {
    "cpu_utilization_pct": 99.9,
    "link_utilization_pct": 100.0,
    "packet_loss_pct": 24.59,
    "latency_ms": 512.51,
    "queue_drops": 9506,
    "interface_errors": 225
  },
  "status": "Critical"
}
```

---

## 2. Field Specifications and Units

| Field Path | Type | Standard Unit | Allowed Ranges / Notes |
| :--- | :--- | :--- | :--- |
| `timestamp` | String | ISO 8601 UTC | Timezone-aware UTC timestamp (e.g. `2026-10-31T12:00:00+00:00`). |
| `device_id` | String | Identifier | Campus switch name matching pattern `SW_CAMPUS_[1-10]`. |
| `status` | String | Enum | Categorical health label: `Healthy`, `Warning`, or `Critical`. |
| `metrics.cpu_utilization_pct` | Float | `percent` (`%`) | CPU utilization percentage (0.0 to 100.0). |
| `metrics.link_utilization_pct` | Float | `percent` (`%`) | Switch link egress bandwidth utilization percentage. |
| `metrics.packet_loss_pct` | Float | `percent` (`%`) | Synthetic dropped packet ratio (0.0% to 30.0%). |
| `metrics.latency_ms` | Float | `ms` | Round-trip packet latency in milliseconds. |
| `metrics.jitter_ms` | Float | `ms` | Packet delay variation (absent in `hardware_failure`). |
| `metrics.queue_drops` | Integer | `packets` | Number of egress queue buffer overflow drops. |
| `metrics.interface_errors` | Integer | `packets` | Physical interface CRC/FCS frame errors (only in `hardware_failure`). |

## 3. Fault Type Signature Matrix

The organizer Colab emits three distinct operational scenarios:

| Metric / Field | `normal` | `latency_spike` | `hardware_failure` |
| :--- | :---: | :---: | :---: |
| `status` | `"Healthy"` | `"Warning"` | `"Critical"` |
| `cpu_utilization_pct` | 10.00 – 35.00% | 40.00 – 70.00% | Constant `99.9%` |
| `link_utilization_pct` | 20.00 – 50.00% | 60.00 – 85.00% | Constant `100.0%` |
| `packet_loss_pct` | `0.0%` | 0.10 – 1.50% | 15.00 – 30.00% |
| `latency_ms` | 5.00 – 20.00 ms | 150.00 – 400.00 ms | 500.00 – 1000.00 ms |
| `jitter_ms` | 1.00 – 5.00 ms | 30.00 – 80.00 ms | **Absent / None** |
| `queue_drops` | `0` | 0 – 50 packets | 5,000 – 15,000 packets |
| `interface_errors` | **Absent / None** | **Absent / None** | 100 – 500 packets |

## 4. Normalization and Adaptation Rules (`gateway/adapters/organizer_adapter.py`)

1. **Metrics Flattening**:
   - The nested `metrics` object is flattened into the root record.
   - Any metric absent in `metrics` is left absent (`None` or omitted), never zero-filled.

2. **Field Alias Mapping**:
   - `cpu_utilization_pct` -> `cpu_pct`
   - `link_utilization_pct` -> `link_utilization_pct`
   - `packet_loss_pct` -> `packet_loss_pct`
   - `latency_ms` -> `latency_ms`
   - `queue_drops` -> `queue_drops`
   - `interface_errors` -> `interface_errors`
   - `jitter_ms` -> `jitter_ms`

3. **Status Mapping**:
   - `Healthy` -> `online`
   - `Warning` -> `degraded`
   - `Critical` -> `degraded` (or `offline` if unreachable/100% loss)

4. **Device Classification**:
   - Devices named `SW_CAMPUS_<n>` are assigned `device_type = "switch"`.
   - Prefixes: `RTR_*` -> `router`, `AP_*` -> `access_point`, `HOST_*` -> `host`. Default fallback: `switch` if campus switch pattern, else `host`.

5. **Timestamp Normalization**:
   - Timestamps are parsed as ISO 8601 UTC.
   - Microsecond precision and trailing `Z` or `+00:00` normalized to standard ISO 8601 UTC strings.

6. **Time-Window Grouping**:
   - When multiple individual snapshot records for the same device exist, they are ordered chronologically and grouped into per-device time windows.

7. **Auto-Detection in `/ingest`**:
   - The Gateway detects the presence of a nested `metrics` key or `status` string (`Healthy`/`Warning`/`Critical`) or top-level list of snapshot records and automatically routes through the `OrganizerAdapter`.
