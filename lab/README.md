# NetCoop AI Lab Emulation Harness

This directory contains the automated network emulation harness and evaluation pipeline used in **Phase 13L** and **Phase 13M**.

The harness stands up real Linux network namespaces connected by `veth` (virtual Ethernet) link pairs, induces live network faults (congestion, carrier flaps, MTU mismatches, CPU stress, and healthy baselines), collects empirical kernel counters and syslog telemetry, and passes them through the NetCoop Gateway adapters in HTTP mode.

---

## 2. Real Kernel Data vs. Harness-Authored Components

To maintain strict scientific integrity, the boundary between live Linux kernel telemetry and harness-synthesized scaffolding is explicitly cataloged:

| Component | Source | Mechanism / Command | Details |
|:---|:---:|:---|:---|
| **Interface State & MTU** | **Real Kernel** | `ip -d -j link show dev <ifname>` | Operstate (`UP`/`DOWN`), exact configured MTU, link flags, txqlen. |
| **Interface Error Counters** | **Real Kernel** | `ip -s -j link show dev <ifname>` | RX/TX bytes, packets, dropped, hardware error counters, carrier changes. |
| **Queue Discard Counters** | **Real Kernel** | `tc -s qdisc show dev <ifname>` | Real kernel egress tail drops generated by Linux Token Bucket Filter (`tbf`). |
| **Path Latency & Loss** | **Real Kernel** | `ping -c <n> -s <sz> -W 1 <ip>` | Empirical round-trip delay and packet loss measured across namespaces. |
| **Host CPU Utilization** | **Real Kernel** | `/proc/stat` delta sampling | Non-idle CPU ticks over a timed sample window under active worker load. |
| **MTU Rejection** | **Real Kernel** | `ping -s 1450 -M do <ip>` | Kernel ICMP "packet too big" rejection when frame exceeds path MTU. |
| **Traffic Stimulation** | **Harness-Authored** | Python raw UDP micro-burst | Sends 1200-byte UDP bursts to saturate the 200kbit rate-limited queue. |
| **Syslog Formatting** | **Harness-Authored** | RFC 3164 & RFC 5424 formatters | Translates kernel fault state changes into standard facility/severity syslog lines. |
| **Topology Metadata** | **Harness-Authored** | JSON nodes and links mapping | Structural graph representation of `core-rtr-01` -> `dist-sw-01` -> `edge-host-01`. |

## 3. Scenarios & Fault Conditions

1. **Link Congestion (`congestion`)**:
   - Kernel Linux Traffic Control (`tc qdisc`) attaches a Token Bucket Filter (`tbf`) with rate limiting and 4KB burst.
   - Micro-burst UDP traffic induces buffer queue overflows and tail drops.
2. **Link Flapping (`link_flap`)**:
   - Linux carrier transitions executed via sequential `ip link set dev <ifname> down` and `up`.
   - Generates real carrier changes, BFD down state transitions, and packet loss.
3. **MTU Mismatch (`mtu_mismatch`)**:
   - `core-rtr-01` configured with MTU 1500; `dist-sw-01` configured with MTU 1400 (or 1480 / 1280).
   - Real `ip -d link` output parsed into device `configurations` section.
   - Oversized DF frames induce interface CRC errors, frame drops, and syslog warnings.
4. **Device CPU Overload (`cpu_stress`)**:
   - Background worker threads execute tight arithmetic loops to spike host CPU utilization.
   - Empirical CPU utilization sampled via `/proc/stat`.
5. **Normal Operation (`healthy_run`)**:
   - Baseline ping, nominal CPU (4-14%), 0 errors, 0 queue drops, 0 link flaps.
   - Evaluated by scope-aware healthy confirmation engine.
